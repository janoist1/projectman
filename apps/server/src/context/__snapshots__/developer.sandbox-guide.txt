# Sandbox guide
Your shell commands run in Claude Code's own sandbox, in your own permission mode: what the sandbox allows runs without asking, and no particular form of command is needed.
- Writing: your working directory `/pm/worktrees/AR/AR-21-app` with its git metadata (not its hooks or configuration), the temp directory (`$TMPDIR`) and `/pm/member-caches/AR/fe-1/npm-cache`, `/pm/member-caches/AR/fe-1/projectman-dev`. Never these paths of the shared git directory (the default branch, the integrating checkout, replacements, server-managed snapshot refs and grafts): `/src/app/.git/refs/heads/main`, `/src/app/.git/HEAD`, `/src/app/.git/index`, `/src/app/.git/packed-refs`, `/src/app/.git/refs/replace`, `/src/app/.git/refs/projectman`, `/src/app/.git/info/grafts` (and their lock files); commit on your own branch.
- Reading: nothing below `/home/anna` and `/pm` except `/pm/worktrees/AR/AR-21-app`, `/pm/member-caches/AR/fe-1/npm-cache`, `/pm/member-caches/AR/fe-1/projectman-dev`, `/pm/member-caches/AR/fe-1/gitconfig`, `/src/app/.git`, `/home/anna/.gitconfig`, `/home/anna/.config/git`, `/home/anna/.claude/shell-snapshots`; everything outside them (the system, the installed tools). Other worktrees, the app's data and the credentials stay closed: do not look for them.
- Your own npm cache and development data: `npm_config_cache` is `/pm/member-caches/AR/fe-1/npm-cache`, `PROJECTMAN_HOME` is `/pm/member-caches/AR/fe-1/projectman-dev`. Leave them set: npm, `npx` and `npm run dev` use them, and the user's `~/.npm` and `~/.projectman-dev` are not writable.
- Git: its system settings come from `/pm/member-caches/AR/fe-1/gitconfig` (`GIT_CONFIG_SYSTEM`; no automatic gc). After a commit git may print `Unable to create '…/packed-refs.lock'`: the commit exists, the shared `packed-refs` is closed to you on purpose; ignore the message, and do not look for a way around it.
- Environment: `GH_TOKEN`, `GITHUB_TOKEN`, `NPM_TOKEN`, `NODE_AUTH_TOKEN`, `SSH_AUTH_SOCK` are unset for your commands.
- Network: any outbound host except `localhost`, `127.0.0.1`; tests may listen on local ports.
- One exception that still waits for a human: a here-document (`<<`). Write files with your file-editing tools and pass text as a quoted argument (`git commit -m '…'`).
- A refusal by the sandbox or by a rule is final: do not retry it in another form or look for a way around it. A test or a check that does not run here goes on the card as a note, not into a question. Anything else you really need, ask a human with ask_human and say why.
